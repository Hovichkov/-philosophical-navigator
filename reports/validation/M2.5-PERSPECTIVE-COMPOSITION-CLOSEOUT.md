## Result in plain language

**1. Удалось ли без нового API key?** Да. Никаких новых ключей, сервисов и оплат не понадобилось.

**2. Каким способом?** Через уже установленный Claude Code CLI в фоновом режиме (`claude -p`). Он работает под вашим обычным входом в Claude, тем же, что у этого чата.
- Каждый вызов изолирован: короткий собственный системный промпт, без инструментов, без MCP, без сохранения сессии.
- Ответ идёт строго по JSON-схеме и затем проверяется контрактом проекта.
- Вызовы расходуют лимит вашего плана Claude: весь прогон — около $2.9 по прайс-листу, примерно $0.15 на кейс.

**3. Для скольких кейсов получены ответы?** **Для всех 20.** 19 прошли проверку с первой попытки, один (B11) — после одной исправляющей попытки: composer получил текст ошибки контракта и ответил заново.

**4. Сколько обычно выбирается перспектив?** Во всех 20 кейсах — **3**. Composer ни разу не воспользовался правом вернуть две. Это стоит учесть при ручной проверке: где-то третья карточка может оказаться слабее первых двух.

**5. Как часто composer отбрасывает Q1 top-1?** В **7 из 20** кейсов (35%): B02, B07, B08, B10, B16, B18, B20. В каждом случае причина записана.

- Разных карточек среди выбранных — 33.
- Чаще других выбирались C0807 (5 раз), C0579 и C0246 (по 4).
- Типичные отказы:
  - ложное семантическое совпадение, например карточка о зависти к чужой доле при вопросе о предательстве;
  - дубль уже выбранного хода;
  - предпосылка, которой нет в рассказе, например «человек мерил должностью свою ценность»;
  - слишком общая или бедная шаблонная карточка.

**6. Ограничения.**
- **Grounding в целом держится:** имён философов, персонажей и текстов сверх метаданных карточки нет; источники подставляет код. Мягкие отклонения всё же есть:
  - **Кавычки вокруг пересказа.** Фразу карточки «я не мог вынести» composer передал как «иначе нельзя» (B05) и «я не мог иначе» (B17). Цитатой выглядит парафраз.
  - **Достраивание бедных шаблонных карточек.** Если у карточки только одна строка сюжета (C0577 в B08, C0713 в B20), composer дополняет мысль общими словами сверх содержания карточки.
- **Пограничные реплики о человеке.** Например, B17: «Похоже, за этим стоит невысказанная мысль…». Сформулировано как предположение, но это ближе всего к диагностике, чего мы избегаем.
- **Иногда перспектива слегка переходит в утешающую рамку.** Например, B20: «растерянность можно считать не поломкой, а первым шагом…».
- **Перекос к восстановленным карточкам.** Среди выбранных их 57%, хотя в корпусе 26%, в Q1 34%. Их perspective — содержательные тезисы, а у 84 карточек — шаблон вокруг пересказа сюжета. Это корпусная асимметрия, известная с M2.3.
- **Composer не детерминирован.** Повторный прогон даст другие формулировки, а иногда и другой выбор. Результаты сохранены как есть и воспроизводятся из пакетов, а не заново генерируются.
- **Метрика — только человеческая оценка.** Автоматического score нет, по заданию. Guard против советов эвристический (список фраз): он ловит явные «вам следует», но не тонкие случаи.
- **Зависимость от CLI.** Composer работает, пока установлен Claude Code и есть вход в аккаунт.

**7. Где файл для ручной проверки?** **`reports/validation/M2.5-COMPOSITION-SAMPLES.md`**. Для каждого кейса там:

## Технические детали

### 1. Архитектура

```
M2.4 trace (один кейс) ──► build_package()  ── детерминированный JSON (sha256), только candidate union
                                 │
                                 ▼
             ClaudeCodeCLIComposer.complete()  ── claude -p --safe-mode --tools "" --strict-mcp-config
                                 │                --no-session-persistence --model claude-opus-5-5
                                 │                --system-prompt <composition-prompt/0.1.0> --json-schema <…>
                                 ▼
                     assemble_result()  ── source = метаданные корпуса (author, work, location)
                                 │
                                 ▼
                     CompositionResult (Pydantic)  ── при ошибке: 1 повтор с текстом ошибки
```

- **Пакет (`build_package`):**
  - confirmed question, context (circumstance, narrative), experiences, working hypotheses, структура запроса;
  - для каждого кандидата union: card_id, source (из корпуса), perspective, philosophical_questions, coordinates, tensions, operation;
  - раздельные сигналы: found_by, ранг и cosine MEANING, ранг STRUCTURE, совпавшие coordinates и tensions;
  - `q1_top_card_id`.

  Весь корпус composer не получает, Thought и fragment не передаются.
- **Промпт** закрепляет правила продукта:
  - не решать и не советовать, не диагностировать;
  - по умолчанию 3 перспективы, можно 2, никогда не больше;
  - relevance с проверкой направленности и субъекта действия, transformative value, distinctness по смыслу, а не по традиции, grounding только по карточке;
  - ранги — только свидетельства;
  - в шаблонных карточках опираться лишь на текст после двоеточия.
- **Файлы:** `src/navigator/models/composition.py`, `src/navigator/composition/composer.py`, `src/navigator/composition/runner.py`, `tests/test_m2_5_composition.py`; в `cli.py` добавлена команда `compose-benchmark` (возобновляемая, `--only`, `--workers`).

### 2. Контракт `CompositionResult`

| правило | где проверяется |
|---|---|
| 2–3 перспективы; при 2 обязателен `fewer_than_three_reason` | схема + валидатор |
| выбранные карточки уникальны, только из candidate pool, не unresolved | валидатор |
| отвергнутые — из пула и не пересекаются с выбранными | валидатор |
| решение по `q1_top` согласовано с выбором | валидатор |
| `source` — только из метаданных корпуса; поле source от модели игнорируется | `assemble_result` |
| reflection question обязателен: один вопрос, оканчивается «?» | валидатор |
| фиксированная первая строка; советы и вердикты блокируются (эвристический список фраз) | валидатор |
| требования разнообразия традиций нет | нет такого поля; промпт явно это запрещает |

Трасса каждого кейса лежит в `compositions/Bxx.json`: candidate pool, выбранные карточки с ролью, заголовком, перспективой, вопросом и `why_selected`, отвергнутые кандидаты с причинами, решение по Q1 top-1, мета (модель, версия промпта, sha256 пакета, число попыток, расход).
