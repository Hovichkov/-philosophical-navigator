## 2. Контракт `QueryRepresentation`

| слой | поля | роль |
|---|---|---|
| **User** | `confirmed_question`; `context {circumstance, narrative}`; `experiences` | главный вопрос retrieval; context и experiences хранятся для trace и последующей оценки, **сигналом не являются** |
| **Interpretation** | `working_hypotheses` (2–4) | рабочие прочтения, не диагноз |
| **Structural** | `coordinates` (только TAXONOMY); `canonical_tensions` (только закрытый список TAXONOMY); `free_tensions` (формат `A ↔ B`, каноническая tension сюда попасть не может) | free tensions taxonomy не расширяют |
| **Provenance** | `origin: benchmark_adapter \| production`, источники вопроса и интерпретации, `benchmark_item_id` | для benchmark-адаптера валидатор требует источников `benchmark_*` и item id |

- `extra="forbid"`: демографические данные, традиция, автор, диагноз и т.п. в запрос не попадут.
- Поля TD D04 `narrative_facts`, `representations`, `question_aspects`, `narrative_constraints`, `retrieval_summary` относятся к qualification и coverage и в M2.2 не входят.

**Benchmark-адаптер** (`benchmark/adapter.py`, явно помечен как не production):
- `confirmed_question` = `center` без внешних «», источник `benchmark_center_proxy`;
- `working_hypotheses` = [semantic_node, различение] из expected structure, источник `benchmark_expected_structure_proxy`;
- `exact` и `reversed_poles` tensions → `canonical_tensions` в TAXONOMY-форме, `case_specific` → `free_tensions` дословно.

## 3. MEANING-документ карточки (`meaning-card-doc/1.0`)

Строится только для 113 retrieval-eligible карточек и только из значений, прошедших `readiness.meaning_inputs` / `structure_inputs`, поэтому заглушки отсечены. Пустые секции опускаются:

```
Перспектива: {perspective}
Философские вопросы:
- {philosophical_questions[i]}
Координаты: {coordinates, через "; "}
Напряжения: {tensions без квалификатора " (potential)", через "; "}
```

- **Не читаются:** Thought, fragment, commentary, context, author, tradition, translation, verification-поля и технические поля.
- Все 113 документов лежат в `data/retrieval/representations/meaning-card-docs.jsonl` (sha256 каждого).
- Пересоздаются командой `navigator export-meaning-docs`.

## 4. Q0 (`q0-question-only/1.0`)

Текст — `confirmed_question` дословно.

- Маршрут: embedding → cosine со 113 MEANING-документами → top_k = 15.
- Это **только контроль для evaluation**, в union не входит.

## 5. Q1 (`q1-meaning-query/1.0`)

```
Вопрос: {confirmed_question}
Рабочие интерпретации:
- {working_hypotheses[i]}
Смысловые напряжения:
- {canonical_tensions..., затем free_tensions...}
```

- context, circumstance, experiences и coordinates не включаются.
- top_k = 15.
- Сохраняются card ID, cosine, rank, точный текст, версия и sha256 запроса, а также версия представления карточек.

## 6. STRUCTURE (без embeddings)

Правило ранжирования (`STRUCTURE_RANKING_RULE`) лексикографическое:
1. больше точных совпадений canonical tensions (квалификатор `(potential)` при сравнении снимается);
2. затем больше точных совпадений coordinates;
3. затем card_id по возрастанию.

- Карточки без единого совпадения не ранжируются.
- `operation` логируется и **никогда не влияет на порядок**.
- top_k = 15.
- Логируются `matching_cards` и `tied_at_cutoff`: сколько равных карточек отрезано границей top_k.

## 7. Candidate union

`union(Q1 top15, STRUCTURE top15)`, Q0 не входит.

- Одна запись на card_id: `found_by`, `meaning_rank`, `meaning_score`, `structure_rank`, `coordinate_overlap`, `matched_coordinates`, `tension_overlap`, `matched_tensions`, `operation`.
- Сигналы другого маршрута — `null`. `final_score` нет.
- Список упорядочен по card_id; это не ранжирование.
- `CandidateRetrievalResult` валидирует, что union равен объединению Q1 и STRUCTURE и что unresolved-карточек в нём нет.

## 8. Embedding-модель и конфигурация

**Default baseline — локальная модель, API key не нужен** (решение владельца, заменяет OpenAI-baseline):

| параметр | значение |
|---|---|
| provider | `local-sentence-transformers` (sentence-transformers 6.1.0, torch 2.14.0) |
| model | **`BAAI/bge-m3`**, dense-выход |
| revision | `5617a9f61b028005a4858fdac845db406aefb181` (зафиксирована) |
| dimensions | 1024 |
| устройство | Apple MPS (M1), fallback — CPU |
| нормализация | L2 (`normalize_embeddings=True`); cosine от неё не зависит |
| префиксы | не используются (bge-m3 их не требует) |
| размер | около 2.27 ГБ весов (`pytorch_model.bin`) в `~/.cache/huggingface`, однократная загрузка; дальше работает офлайн (`HF_HUB_OFFLINE=1`) |

- **Почему bge-m3:** сильная открытая multilingual-модель для retrieval с хорошими результатами на русском. Не требует инструкционных префиксов, так что форматы Q0, Q1 и MEANING-документов не изменились. Работает на Apple Silicon.
- **Выбор провайдера:** `navigator run-benchmark-retrieval --embedding-provider local|openai`, по умолчанию `local`.
- **OpenAI** (`text-embedding-3-large`, 3072) остаётся опциональным провайдером за тем же `EmbeddingClient`, ключ читается только из env.
- **Similarity:** cosine, NumPy brute-force in-memory, без vector DB.

## 9. Кэш

- Путь: `data/retrieval/embeddings/<provider>__<model>__<revision[:12]>__<dims>/<namespace>/{index.json, vectors.npy}`.
- Namespaces: `meaning-cards`, `queries`.
- Идентичность конфигурации: provider + model + **revision весов** + dims. Она входит и в имя директории, и в `index.json`: индекс с другой конфигурацией игнорируется, клиент с другой конфигурацией отклоняется.

## 15. Вопросы, оставленные для M2.3 (не решались, корпус и retrieval не правились)

0. **Сильный перекос Q1 к восстановленным первым 29 карточкам.** Они занимают 85% мест Q1 top-15 при доле 25.7% в корпусе. C0056 входит в top-15 во всех 20 кейсах, всего в Q1 появляется 51 карточка из 113. Наиболее вероятная гипотеза для проверки — асимметрия MEANING-документов (п. 3 ниже): у 95 textual-pass карточек общая шаблонная обвязка, у восстановленных её нет. Это эмпирическое подтверждение, причина не локализована.

1. **Ничьи в STRUCTURE.** Лексикографическое ранжирование грубое: в B05, B06, B07, B14, B15, B18 и B20 за границей top-15 остаются от 26 до 68 равных карточек. Tie-break по card_id систематически продвигает карточки с меньшими ID. Нужен содержательно нейтральный способ обращаться с ничьими (без подобранных весов).
2. **Free tensions.** В B06, B07, B15, B17 и B20 ни одна canonical tension не совпала: их tensions почти целиком case-specific. STRUCTURE фактически работает только по coordinates, а free tensions учитывает лишь Q1.
3. **Асимметрия представлений:**
   - у 95 textual-pass карточек в MEANING-документе шаблонная обвязка (общие вопросы, префикс perspective), у 29 восстановленных её нет;
   - у многих шаблонных карточек coordinates = «действие; отношение к себе», а у восстановленных карточек из реестра их больше, что влияет на STRUCTURE-overlap;
   - эффект на cosine пока не измерен.
4. **Контрастные варианты без confirmed question и гипотез.** Нужно решение: расширить спецификацию M2.1 или ввести отдельную конвенцию для контрастных прогонов.
5. **Слияние `BenchmarkRunTrace` с полной `RetrievalTrace`** TD D27/D45; сохраняются открытые вопросы M2.1 о размере финального набора (3–5 против 2–3) и о границе confirmed question.
6. **Коммит артефактов.** Хранить ли векторы и прогоны в репозитории, решит владелец, когда появится git.
